## No more ZCode icons in the Dock

0.2.0 could leave several black "exec" icons named ZCode in the Dock, marked as not responding. This release fixes both causes.

- **Updating ccx no longer disturbs a running ZCode.** Installing or updating ccx's plugin while ZCode was open made ZCode restart its built-in tool servers (documents, spreadsheets, slides, PDF, site), and macOS showed each of them as an unresponsive app in the Dock. ccx now leaves a running ZCode's plugins alone and installs the update the next time ZCode is closed. If you still see those icons, quit ZCode and open it again.
- **ccx's own work with ZCode stays out of the Dock.** Each time ccx ran ZCode's command-line agent (while installing its plugin, and once per import into ZCode), an extra ZCode icon showed until that run ended. ZCode's agent renames its process, and on macOS that registers it as an app; ccx now keeps the name as it is.

If you are on the script, `ccx update` picks this release up on its own. The app download is below.

0.2.0 可能会在 Dock 里留下几个名叫 ZCode 的黑色 "exec" 图标，显示"应用程序没有响应"。这一版把两个原因都修好了。

- **更新 ccx 不再打扰正在运行的 ZCode。** 以前在 ZCode 开着时安装或更新 ccx 插件，ZCode 会重启它自带的工具服务（文档、表格、演示文稿、PDF、站点），macOS 会把每一个都显示成 Dock 里一个"没有响应"的应用。现在 ZCode 开着时 ccx 不动它的插件，等下次 ZCode 关闭后再装。如果还能看到这些图标，退出 ZCode 再打开即可。
- **ccx 自己调用 ZCode 时也不会再出现在 Dock 里。** 以前 ccx 每次调用 ZCode 的命令行（安装插件时，以及每次导入到 ZCode 时），Dock 里都会多一个 ZCode 图标，直到那次调用结束。原因是 ZCode 的命令行会给自己的进程改名，在 macOS 上这样会被登记成应用；ccx 现在不让它改名。

已经在用脚本的，`ccx update` 会自己更新到这一版；App 下载见本页附件。
